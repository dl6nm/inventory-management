System Architecture

A three-tier demo app. There is no database: JSON files are loaded into Python memory once when the server starts, and every request is filtered in memory.

Request Data Flow

What happens when a user changes a filter, for example Warehouse = "San Francisco" on the Dashboard.

FilterBarThe user picks a value. It is stored in a shared ref in useFilters.
WatcherThe view watches the filter refs and calls getCurrentFilters().
api.jsDrops filters set to "all" and builds a ?warehouse=... query string.
FastAPIRuns apply_filters(), then filter_by_month(), on the in-memory lists.
PydanticThe response is validated against the model and serialized to JSON.
ComputedRaw data goes into refs, and KPIs and charts are recomputed as computed values.

Key rules

  • Inventory has no time dimension, so month is ignored for it.
  • Category and status matching ignore case. Warehouse must match exactly.
  • Quarter values such as Q3-2025 expand to 3 months, which are matched as substrings of order_date.
  • Backlog and demand data are never filtered.
  • Low stock means quantity_on_hand <= reorder_point.

Observations

Gaps found during the investigation.

Missing endpoints. api.js calls /api/tasks (used by App.vue) and /api/purchase-orders, but main.py defines neither, and both return 404.
Unrouted view. views/Backlog.vue exists but is not registered in the router in main.js. Backlog data is shown through the Dashboard instead.
Read-only, in-memory data. All data is loaded once at import time. Any writes would be lost on restart, and the data assumes 2025 dates (QUARTER_MAP is hard-coded).
Open CORS. allow_origins=["*"] with credentials enabled is acceptable for a local demo, but not for production.
